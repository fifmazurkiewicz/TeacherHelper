# Problem Framing

Read existing project instructions and relevant Graft knowledge first; use
focused `rg` if Graft is unavailable. For the active change, create
`frame.md` with the observed problem, affected users or systems, constraints,
success criteria, assumptions, and competing explanations.

Do not select an implementation, invent missing business rules, or treat a
requested fix as proof of root cause. Resolve uncertainty with the human owner
when it changes scope or success criteria. Hand off the validated frame to
technical research.
