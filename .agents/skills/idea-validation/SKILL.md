# Idea Validation

Clarify whether the team has enough evidence to shape a solution. This is a
decision aid, not a unilateral go/no-go gate.

## Output

Capture, in proportion to the decision:

1. Problem and target user.
2. Pain, current alternatives, and why they fall short.
3. Expected business or user value.
4. Evidence, assumptions, and confidence level.
5. Risks and unknowns.
6. The cheapest useful validation step when evidence is insufficient.

State what is known, unknown, and assumed. Do not invent research, promise a
market outcome, select an architecture, or duplicate solution shaping.

## Happy path

```text
Idea -> idea-validation -> brainstorming -> production-product-requirements
-> writing-plans -> implementation/review
```

Start at the earliest missing stage. Skip this skill for an already-decided,
narrow maintenance change; use `brainstorming` when the problem is accepted
and the remaining question is how the solution should work.
